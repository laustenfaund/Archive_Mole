01

Importing conversations

On first launch, Archive Mole is a single drop target. There's nothing to configure — you feed it export files and it builds your archive from what's inside them.

  1. Export your conversations from ChatGPT (Settings → Data Controls → Export data) or Claude. You'll get an email with a download link to a .zip; unzip it to get the .json file(s) inside.
  2. Drag the .json file onto the dashed drop zone, or click anywhere inside it to open a file picker. You can select several files at once.
  3. A progress bar fills while each file is read. When it finishes, the dashboard replaces the drop zone.

What Archive Mole actually reads

ChatGPT's export stores each conversation as a tree of linked message nodes; Archive Mole walks that tree from root to the last child at each step to reconstruct the back-and-forth, then strips ChatGPT's inline citation markers out of the text. Claude.ai's export stores each conversation as a flat list of messages instead, and Archive Mole reads that shape directly too — both formats land in the same archive.

Platform is detected from the file's own shape: a Claude.ai–shaped file is always labeled claude; a ChatGPT-shaped file is labeled claude only when its recorded model name contains "claude" (useful for aggregated or multi-model exports), and chatgpt otherwise.

Only files ending in .json are accepted by drag-and-drop; anything else dropped onto the zone is quietly ignored.

02

The dashboard

Once conversations are loaded, the top of the page becomes a small stats strip:

Conversations

Total conversations across every file you've loaded.

Messages

Total user and assistant messages across all of them.

Words

Combined word count, shown in thousands.

Files

Number of distinct export files loaded so far.

Below the count, the earliest and most recent conversation dates in your archive are shown as a range. A + add files button stays available here for loading more exports later, and a brief button opens the search brief editor.

03

Browsing conversations

Results appear as a list of cards, one per conversation, newest first by default. Each card header shows the title, platform, message count, and a preview drawn from the first user message. Click anywhere on the header to expand it into the full thread, and click again to collapse it.

Inside an expanded thread, messages are labeled by who sent them. A message longer than 1,200 characters is cut off with a show full message (N more chars) button beneath it — click it to reveal the rest in place.

Results are paginated at 25 conversations per page, with prev / next controls and a page counter at the bottom of the list. Changing page scrolls you back to the top.

04

The timeline

A row of bars above the results shows one bar per month that has at least one conversation in it, with bar height scaled to that month's volume. Hovering a bar shows the exact month and count; clicking it filters the whole list down to that month by setting the date range for you. A clear control next to the date fields resets both bounds and deselects the bar.

05

Searching

Type a word or phrase into the search box and press Enter to add it as a search term. You can add several terms this way — each becomes its own removable chip above the results, and clear removes all of them at once.

A search checks each conversation's title, its preview snippet, and the text of every message. A title match counts for more than a body match when ranking results, so a term that names the conversation tends to surface it first under Relevance sort.

Once you have two or more terms, a match-mode row appears:

Match modes
ModeBehavior
any termKeeps a conversation if it contains at least one of your terms (OR).
all termsKeeps a conversation only if every term appears somewhere in it (AND).
exact phraseTreats all your terms joined together as one literal phrase, rather than matching them separately.

Adding your first term automatically switches the sort dropdown to relevance. You can change it any time to most recent, oldest first, or most messages — the last three work with or without an active search.

06

Filtering

Three filters combine with search and sort, all narrowing the same list at once:

Platform

Chips for all / chatgpt / claude restrict the list to one detected platform.

Date range

Two date fields filter by each conversation's last-updated time (or created time, if never updated).

Tags

A row of your own tags appears once you've tagged something — click one to filter to it, click again to clear.

07

Tags

Every conversation card has a + control for adding a tag: type a short label and press Enter, or click add. Tags are lowercased and stripped down to letters, numbers, spaces, and hyphens — anything else is dropped silently. A conversation can carry several tags at once, shown as chips on its card with their own remove button.

Tags are entirely yours: Archive Mole never generates or suggests them from content. Once at least one exists anywhere in your archive, the tag filter row in Filtering lists every tag in use so you can jump straight to that slice of your archive.

08

Searching inside a thread

An expanded conversation has its own Search within this conversation... box, separate from the main search bar above the list. Typing here highlights matching messages within that thread and shows a running current / total match count, with ↑ / ↓ controls that jump between hits and wrap around at the ends.

This search only affects your position inside the conversation you already have open — it doesn't change which conversations are in your results, so it's the tool for pinpointing a moment once the main search or filters have gotten you to the right thread.

09

The search brief

The brief button opens a plain text editor, pre-loaded with a procedure for working through a large personal archive deliberately rather than skimming it — written to be handed to an AI assistant as its instructions for the session. Archive Mole doesn't run this itself; it's a starting point you copy out and use alongside the app's own filters.

Default brief7 phases
  1. Scope first. Establish the topic, time range, anything to exclude, and the output form — without leading questions.
  2. Narrow before reading. Apply the platform, date, and tag filters to the working set before opening any conversations.
  3. Catalog, don't read yet. Run keyword searches across the scoped set and record what exists and where, by time period.
  4. Flag high-signal candidates. Based on recurring themes, dense keyword hits, or tags you've applied — keeping a record of lower-priority items rather than discarding them.
  5. Read only what's flagged. Pull short verbatim snippets as grounding; anything not directly observed stays out, or is clearly marked as inference.
  6. Write in chunks. Match the time range, apply the exclusion rules throughout, and pause for a go-ahead between chunks.
  7. Extend, don't restart. When new exports are added later, only re-run the cataloging phase on the new material and merge it into the existing results.

Edit the text freely — trim it, add your own rules, or replace it outright — then save to keep your version for next time. close discards any unsaved changes and reopens the saved version (or the default above) next time.

10

Data & privacy

Archive Mole is a single HTML file with no server behind it. Everything it parses — conversations, tags, your saved brief — is written to this browser's local database on this device, and nothing is ever sent out over the network.

What that means in practice

Your archive is tied to this browser, on this device. Opening the file in a different browser, a different profile, or a different computer starts from empty — it doesn't sync. Clearing this browser's site data for the file deletes your archive along with it.

There's no export

Archive Mole has no built-in backup or export feature — your only durable copy is the original export .json file(s) from ChatGPT and Claude. Keep those; re-importing them is how you'd rebuild the archive on another browser or device.

If local storage fills up or becomes unavailable, a banner appears warning that recent changes may not survive a reload. Free up space, or avoid loading more files, until it clears.

Troubleshooting

SymptomWhat's happening
A file imports but adds zero conversations The file isn't a ChatGPT or Claude.ai conversation export, or it's been altered from its original shape (see Importing conversations). Files exported directly from either platform should always work.
A ChatGPT-exported conversation you expected to be tagged Claude shows as ChatGPT For ChatGPT-shaped files, platform is guessed from the model name recorded in the export. If that name doesn't contain "gpt", "o1", "o3", "o4", or "claude", it defaults to ChatGPT. A genuine Claude.ai export is unaffected by this — it's always detected by its file shape, regardless of model name.
Dropping a file does nothing Drag-and-drop only accepts files ending in .json; anything else is ignored. Use + add files to pick from a file dialog instead.
Re-adding a file doesn't seem to change anything Expected — a file already loaded (by filename) is skipped, and any conversation ID already in your archive is skipped even if it arrives in a different file.
A "storage full" warning appears This browser's storage quota for the file is exhausted. See Data & privacy.
